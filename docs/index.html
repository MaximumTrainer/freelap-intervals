How it works

Four steps, fully verified

Import from CSV or the MyFreelap web backend. The app matches your session to a watch activity, writes the data, then reads it back to confirm.

01

Import

Upload a CSV or fetch from MyFreelap. Sessions are normalised into a canonical model.

02

Match

03

Write

Intervals, custom fields, and a rep table land on the activity. Or a synthetic FIT is uploaded.

04

Verify

The activity is read back and compared field by field. Every difference is reported.

Built for trust

Features

Every design choice optimises for data integrity: your training data is yours, and this app never corrupts it.

Rollback on failure

If a write fails mid-way, completed steps are reversed automatically. In create mode the orphan activity is deleted; in attach mode a snapshot is restored.

Content-hash skip

Re-syncing an unchanged session skips the write but still re-verifies, so you always know the current state without wasting API calls.

Offset suggestion

Cross-correlates Freelap rep timings against the watch speed trace to suggest a clock offset. You can always override with the slider.

Envelope encryption

Every credential is encrypted before it reaches the database, with per-credential keys wrapped by a master key. Nothing is ever logged in the clear.

Per-athlete queue

Background jobs are round-robin by athlete, so one person's backlog never delays another. At most one job per athlete runs at a time.

Adapter canary

A nightly health check against a test account detects MyFreelap changes before athletes hit them. Degradation triggers alerts and a CSV fallback.

Get started

Up and running

No Docker needed for development. Postgres runs in-process via PGlite.

1

Clone and install

git clone the repo, then npm install. That's it — no external services.

2

Run the gate

npm run check runs typecheck, lint, and all 588 tests against an in-process Postgres.

3

Configure

Copy .env.example to .env and fill in your secrets and intervals.icu OAuth credentials.

4

Start the app

npm run migrate, then npm run web and npm run worker in separate terminals. Or use docker compose up.

5

Or use the CLI

Set INTERVALS_ICU_ATHLETE_ID and INTERVALS_ICU_API_KEY, then npm run sync -- import, plan, push, verify.

Architecture

Ports and adapters

Pure domain at the centre. Everything the outside world can change sits at the edge behind an interface.

Domain

SprintSession, interval naming, timezones, durations. No I/O, no clock, no env.

App

SyncApplication: import, plan, sync, verify. The only orchestrator.

Ingest

CSV normalisation and the flag-gated MyFreelap web adapter.

Match

Ranks candidates by date, duration, and speed-peak correlation.

Write

Timeline placement, interval planning, FIT encoding. Rollback on failure.

Verify

Reads back every field and reports diffs against intent.

Security

Envelope encryption, CSRF, session store, rate limiting.

Jobs

Postgres queue with per-athlete round-robin and canary scheduling.

Web

Server-rendered HTML. Connect, import, review with offset slider, sync, verify.

CLI

Single-athlete, no-database path. API key only.
